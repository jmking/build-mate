# Security and data

For a vulnerability, use [GitHub’s private vulnerability reporting](https://github.com/jmking/build-mate/security/advisories/new). Do not put credentials, private repository contents or sensitive logs in a public issue. This project is an early preview; use the latest release.

Build Mate runs coding agents, Git and configured shell hooks as your macOS user. Hooks and local previews are trusted commands you choose; the app itself is not an App Sandbox container. By default, task agents have explicit worktree/Git write permissions, and project chat is read-only. Native approval cards let you review requests for additional access. Task approval modes can inherit from a project or be overridden per task: Ask for approval uses human decisions, Approve for me uses Codex's automatic reviewer, and Full Access disables Codex's filesystem/network sandbox and command prompts. Changing a running task's mode restarts its turn in the same conversation. Full Access also applies to app-run QA checks and capture commands; other modes retain their restricted QA sandbox. Plan/review approvals, connected-service confirmations and macOS privacy prompts remain separate. These boundaries do not make untrusted repository code safe to build or execute.

Codex, GitHub CLI and TWG CLI retain their own credentials. Signing/notarization credentials stay in the maintainer’s Keychain. Build Mate does not require you to paste tokens into a chat. Permission grants apply only to the displayed request or current turn, never a persistent command rule. Unsupported secret-entry requests and structured connected-tool forms are declined; finish authentication in the tool that owns it. Requests from unknown threads or previous runs cannot be approved.

Chat history, attachments and logs are stored under `~/Library/Application Support/Build Mate/`; task and project-chat worktrees use `~/.build-mate/worktrees/`. Development builds use separate data and worktree roots. Content sent to an agent is processed by the configured Codex service/account. PRs, comments and commits are sent to GitHub when those workflows run. There is no Build Mate cloud backend or analytics service.

Inspect logs and attachments before sharing them: automated redaction is not a guarantee that all sensitive repository content has been removed. Deleting a task removes its app-owned data and worktree, but not its existing GitHub PR or Git branch. Back up work you need before deleting it.
