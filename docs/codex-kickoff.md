# Codex kickoff prompt (v1, Mac)

Paste this into Codex from the repository root.

---

You're building **Build Mate v1: the native macOS app only**. Everything you need is in this repository. Nothing about iPhone, remote access, Linear/Jira, a Claude runner or "ship as one PR" is in scope.

**Read first, in this order:** `AGENTS.md` (how we work, stack, testing rules), `docs/spec/00-index.md`, then `docs/spec/01`–`04`, `06`, `07`, `08`, and `docs/design/README.md` (skim every `mac-*` PNG in light and dark). The Codex app-server protocol schema is in `docs/reference/codex-app-server-schema/`.

**Tech choices (fixed):** Swift 6 with strict concurrency, SwiftUI (AppKit only where SwiftUI lacks a control), minimum macOS 26, built with the installed Xcode. One app process: no helper daemon, no XPC, no server. Xcode project generated by XcodeGen from `project.yml`. SQLite via GRDB is the only planned dependency. Agents run through `codex app-server` over stdio. GitHub via the `gh` CLI, Bitbucket Cloud via the `twg` CLI, git via the `git` CLI. Build with system controls, materials (Liquid Glass), SF Symbols and system colours, matching the designs.

**How to work:** follow the milestones in `docs/spec/07-delivery.md`, one at a time, each ending with its acceptance criteria passing and a short demo note in your final message. Keep it as simple as `AGENTS.md` demands. Commit small, coherent changes. When the spec is ambiguous, take the simplest reasonable reading, record it in `docs/spec/08-open-questions.md`, and continue.

**Start with milestone 1 (spikes), then milestone 2 (core):**
1. Spike the Codex app-server against the real `codex` on this Mac: start a thread in a scratch git worktree, run turns, `turn/steer`, `turn/interrupt`, `thread/resume` after restarting the process, read rate limits, and decide how Build Mate's agent tools are registered (dynamic tools vs. per-session MCP server). Write the findings into `docs/spec/08-open-questions.md` and adjust `03-integrations.md`.
2. Spike the `twg` CLI for Bitbucket Cloud: map each operation in `03-integrations.md` §3 to an exact command (or the REST fallback) and record them. If `twg` isn't installed or set up, tell me the exact steps and continue with GitHub.
3. Scaffold the app (`project.yml`, app target, test target), the SQLite store and data model (`02-architecture.md` §4), the task state machine (§5) and the orchestrator loop with worktrees, hooks, retries and reconciliation (§6).
4. Build the e2e test harness described in `AGENTS.md`: fake `codex`, `gh` and `twg` executables on `PATH`, plus a local bare git remote. Write the first e2e test for the main flow: task created in Todo, the agent asks a question, it's answered, the agent builds, proof passes, human review, Open Pull Request, merged, done. Add a unit test for the state machine's transition rules only.

Stop after milestone 2 and report: what works, what the spikes found, any spec changes you made, open questions for me, and the exact commands to build, test and run.
